# LLM-GIS Docker + PostGIS Backend Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement a deterministic Docker Compose architecture (PostGIS + headless agent toolbox) that ingests vectors/rasters, validates CRS/geometry, runs spatial SQL, and exports results via non-interactive entrypoints.

**Architecture:** Two containers: `db` (`postgis/postgis:17-3.5`) and `agent` (GDAL toolbox + uv-run CLIs). The agent reads `/data/incoming` (ro), writes `/data/work` and `/data/outgoing` (rw), and executes ingestion/analysis/export through `bin/*` commands.

**Tech Stack:** Docker Compose, Postgres 17 + PostGIS 3.5 (incl. raster), GDAL/PROJ/GEOS CLI, `uv` + Python 3.12, `psql` + `ogr2ogr` + `gdalwarp` + `raster2pgsql`.

## Task 2: Add Docker Compose baseline (db + agent)

**Files:**
- Create: `docker-compose.yml`
- Create: `docker/db/init/00_extensions.sql`
- Create: `docker/db/init/10_schemas.sql`

**Step 1: Compose services**
- `db` service:
  - image: `postgis/postgis:17-3.5`
  - env: `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`
  - volume: `pgdata:/var/lib/postgresql/data`
  - mount init scripts: `./docker/db/init:/docker-entrypoint-initdb.d:ro`
  - healthcheck: `pg_isready -U $POSTGRES_USER -d $POSTGRES_DB`
- `agent` service:
  - build: `docker/agent/Dockerfile`
  - env: `DATABASE_URL` or `PG*` env vars
  - mounts:
    - `./data/incoming:/data/incoming:ro`
    - `./data/outgoing:/data/outgoing:rw`
    - `./data/work:/data/work:rw`
    - `.:/workspace:rw`
  - workdir: `/workspace`

**Step 2: DB init scripts**
- `00_extensions.sql` creates:
  - `postgis`, `postgis_raster`, `hstore`, `uuid-ossp`
- `10_schemas.sql` creates:
  - schemas `meta`, `raw`, `analysis`
  - table `meta.ingestions` minimally:
    - `ingest_id text primary key`
    - `input_path text not null`
    - `input_hash text not null`
    - `detected_crs text`
    - `chosen_crs text`
    - `status text not null`
    - `created_at timestamptz not null default now()`
    - `updated_at timestamptz not null default now()`
    - `report_path text`
    - `log_dir text`

**Step 3: Verification**
- Run: `docker compose up -d db`
- Run: `docker compose exec -T db psql -U gis -d gis -c "SELECT PostGIS_Full_Version();"`
- Expected: returns PostGIS version info without manual steps.

## Task 5: Implement dataset staging (`stage`)

**Files:**
- Modify: `llm_gis/cli.py`
- Create: `llm_gis/stage.py`

**Step 1: Staging behavior**
- Copy (or unpack) from `/data/incoming/...` into `/data/work/staging/<ingest_id>/`.
- Compute and store an input hash (SHA256 over file bytes; directory = stable sorted walk).
- Emit `report.json` to `/data/work/reports/<ingest_id>.json` with:
  - input paths
  - hash
  - staging path
  - timestamps

**Step 2: Verification**
- Run (example): `docker compose run --rm agent uv run llm-gis stage /data/incoming/sample.gpkg`
- Expected: a new staging folder and report JSON appear under `/data/work`.

## Task 6: Implement inspection (`inspect`) for vectors and rasters

**Files:**
- Modify: `llm_gis/cli.py`
- Create: `llm_gis/inspect.py`

**Step 1: Vector inspect**
- Execute `ogrinfo -json` and parse:
  - layers, geometry types, feature counts
  - detected CRS (authority when possible)
  - extent/bounds

**Step 2: Raster inspect**
- Execute `gdalinfo -json` and parse:
  - raster size, bands, nodata, dtype
  - SRS and geotransform
  - bounds

**Step 3: CRS suspicion heuristics**
- If CRS missing: mark `crs_status="missing"`.
- If CRS present but suspicious: mark `crs_status="suspicious"` and include a reason string.
- Else: `crs_status="ok"`.

**Step 4: Verification**
- Run: `docker compose run --rm agent uv run llm-gis inspect /data/incoming/...`
- Expected: report JSON includes `crs_status` and the parsed metadata.

## Task 7: Implement vector ingestion (`ingest-vector`) using ogr2ogr + SQL normalization

**Files:**
- Modify: `llm_gis/cli.py`
- Create: `llm_gis/ingest_vector.py`
- Create: `llm_gis/sql/normalize_vector.sql`

**Step 1: Preconditions**
- Refuse to ingest if `crs_status` is missing/suspicious unless `--src-crs` is provided.

**Step 2: Create per-ingest schema**
- `CREATE SCHEMA IF NOT EXISTS raw_<ingest_id>;`

**Step 3: Load via ogr2ogr**
- Use `ogr2ogr` into `PG:` DSN targeting `raw_<ingest_id>.<table>`.
- Use explicit geometry column name `geom`.

**Step 4: Normalize geometry**
- Run SQL to:
  - count invalid geometries
  - `ST_MakeValid`
  - enforce 2D (`ST_Force2D`)
  - create spatial index

**Step 5: Record metadata**
- Upsert `meta.ingestions` row:
  - detected CRS, chosen CRS, row counts, invalid counts, status

**Step 6: Verification**
- Run: `docker compose run --rm agent uv run llm-gis ingest-vector ...`
- Query: `SELECT COUNT(*) FROM raw_<id>.<table>;`
- Expected: rows present, geometry is valid or fixes are recorded.

## Task 8: Implement raster ingestion (`ingest-raster`) using gdalwarp + raster2pgsql

**Files:**
- Modify: `llm_gis/cli.py`
- Create: `llm_gis/ingest_raster.py`

**Step 1: Preconditions**
- Same CRS rules as vectors.

**Step 2: Optional reprojection**
- If `--dst-crs` provided, run `gdalwarp` into `/data/work/staging/<id>/warped.tif` (or similar).

**Step 3: Load to PostGIS raster**
- `raster2pgsql -s <srid> -I -C -M <tif> raw_<id>.<table> | psql ...`

**Step 4: Verification**
- Run: `SELECT ST_SRID(rast) FROM raw_<id>.<table> LIMIT 1;`
- Expected: SRID matches chosen CRS; table populated.
